# LeadPilot API

FastAPI backend for LeadPilot. This is a **starter scaffold**: the architecture,
wiring, and tooling are complete, but no domain models exist yet.

## Requirements

- Python 3.12 (the venv is already created at `.venv`)
- PostgreSQL 16, or SQLite for a zero-setup local run
- Docker (optional)

## Getting started

```powershell
# 1. Activate the venv
.\.venv\Scripts\Activate.ps1

# 2. Install dependencies
pip install -r requirements-dev.txt

# 3. Create your local config
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(32))"   # paste into SECRET_KEY

# 4. Run
uvicorn app.main:app --reload
```

Docs are then at <http://localhost:8000/docs>.

To run without installing PostgreSQL, set this in `.env`:

```env
DATABASE_URL=sqlite+aiosqlite:///./leadpilot.db
```

### With Docker

```powershell
docker compose up --build
```

## Project layout

```
app/
  main.py              # App factory, middleware, lifespan
  api/
    deps/              # Injectable dependencies (DbSession, CurrentUser, Pagination)
    v1/
      router.py        # Aggregates all v1 routes
      routes/          # One module per resource
  core/
    config.py          # Settings from environment
    security.py        # Password hashing, JWT encode/decode
    exceptions.py      # Error types + handlers (one JSON error shape)
    logging.py         # structlog setup
  db/
    base.py            # Declarative Base, TimestampMixin, model registry
    session.py         # Async engine + session factory
    migrations/        # Alembic
  models/              # SQLAlchemy ORM models
  schemas/             # Pydantic request/response models
  repositories/        # Query logic, one per model
  services/            # Business rules, owns transactions
tests/
docker/
```

### The layering rule

```
route -> service -> repository -> model
```

- **Routes** parse input and return schemas. No business logic, no queries.
- **Services** hold the rules and call `commit()`. They raise `AppError`
  subclasses; the handlers in `core/exceptions.py` turn those into JSON.
- **Repositories** own all SQLAlchemy. Nothing above this layer writes a query.

Every error response shares one shape:

```json
{ "error": { "code": "not_found", "message": "...", "details": null } }
```

## Adding a resource

1. `app/models/lead.py` — the ORM model, then import it in `app/db/base.py`
   so Alembic autogenerate can see it.
2. `app/schemas/lead.py` — `LeadCreate`, `LeadUpdate`, `LeadRead`.
3. `app/repositories/lead.py` — `class LeadRepository(BaseRepository[Lead])`.
4. `app/services/lead.py` — the rules.
5. `app/api/v1/routes/leads.py` — the endpoints, then register the router in
   `app/api/v1/router.py`.
6. `alembic revision --autogenerate -m "add leads"` then `alembic upgrade head`.

## Migrations

```powershell
alembic revision --autogenerate -m "describe the change"
alembic upgrade head
alembic downgrade -1
```

Review every autogenerated migration before applying it — autogenerate misses
renames and some constraint changes.

## Tests

```powershell
pytest
```

Tests run against in-memory SQLite, so no database is required. `tests/conftest.py`
overrides the `get_db` dependency and builds a fresh schema per test.

## Connecting the frontend

The Vue app reads `VITE_API_BASE_URL` (default `/api`) and sends
`Authorization: Bearer <token>`, taking the token from a **non-HttpOnly**
`accessToken` cookie it sets itself. So the login endpoint must return the token
in the JSON body — an HttpOnly cookie would be invisible to it.

In the frontend's `.env`:

```env
VITE_API_BASE_URL=http://localhost:8000/api/v1
```

`BACKEND_CORS_ORIGINS` in this project's `.env` already allows the Vite dev
origin (`http://localhost:5173`).

## What is intentionally left unimplemented

`app/models/` is empty, and the `auth`/`users` route bodies raise
`NotImplementedError`. The auth contract (register/login/refresh/me), the
`BaseRepository`, and `BaseService` are in place to build against — add a `User`
model and wire the TODO in `app/api/deps/auth.py` to a real lookup.
